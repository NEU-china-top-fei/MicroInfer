# P6: 追上 nano-vllm 的 kernel 与边界开销

P5 之后 MicroInfer 与 nano-vllm 的差距是 1.01–1.12×。P6 针对四个具体热点做了
优化，没有改变调度、KV 管理或 API。

## 结果

Qwen3-0.6B、RTX 4060 Laptop 8 GB、`block_size=16`、`num_blocks=1024`、
`--compile-ops --use-cuda-graph`、`max_num_prefill_tokens=8192`、cold cache、
3 次中位数：

| workload | P5 tok/s | P6 tok/s | P5 TTFT | P6 TTFT | P5 TPOT | P6 TPOT |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| single-short | 147.4 | 148.3 | 17.1 ms | **15.2 ms** | 6.4 ms | 6.5 ms |
| batch8-short | 906.2 | 906.0 | 50.5 ms | 49.9 ms | 7.4 ms | 7.5 ms |
| batch32-mixed | 1380.6 | 1385.2 | 386.6 ms | **376.7 ms** | 11.5 ms | 11.5 ms |
| shared-prefix | 915.1 | 918.7 | 25.2 ms | **19.4 ms** | 8.2 ms | 8.4 ms |
| long-prefill | 83.9 | **88.3** | 125.7 ms | 123.8 ms | 8.2 ms | **7.6 ms** |

单机运行间波动约 ±2%。相对 nano-vllm（154.1 / 974.7 / 1412.2 / 927.4 / 93.8
tok/s）为 **1.04× / 1.08× / 1.02× / 1.01× / 1.06×**。shared-prefix 的 TTFT
已持平（19.4 ms），long-prefill 从 1.12× 收到 1.06×。

## 1. Split-K paged decode

文件：`microinfer/layer/triton_paged_attention.py`

- 每个 program 仍负责一个 `(request, query head)`，保持 P3 的寄存器布局；
- 当 `num_requests * num_q_heads < 64` 时启动 `split_k=4`，program 以
  `tile = split, split + 4, ...` 的 stride 扫描 context；
- 每个 split 只写 `(m, l, acc)`，`_paged_decode_reduce_kernel` 用 FP32 合并；
- split 数是 launch 常量，所以能进 CUDA Graph；上下文长度变化只影响循环次数；
- batch 足够大时直接写 output，不分配 workspace，也不启动 reduce kernel。

这解决了单请求 2K context 只有 16 个 program 的问题，long-prefill 的 TPOT
从 8.2 ms 降到 7.6 ms。也试过"一个 program 处理整个 GQA group"以减少 K/V
读取，但 2D softmax 状态 + 3D 广播在 8 warps 下寄存器压力过大，batch 吞吐
下降约 10%，已回退；当前版本保留 per-head 布局。

## 2. Paged prefill，去掉 gather

文件：`microinfer/layer/triton_paged_attention.py::triton_paged_prefill`

原路径对每个请求、每一层执行 `index_select + cat`，把有效 K/V 复制成连续
张量再调用 varlen FlashAttention。共享前缀 workload 是 8 请求 × 544 token，
每层约 16 次小拷贝，28 层约 400 次 launch，且复制量远大于 query。

新 kernel：

- grid = `(ceil(max_q_len / BLOCK_M), Hq, requests)`，`BLOCK_M=16`、`BLOCK_N=32`；
- 直接从 block table 读 K/V，causal mask 用绝对位置 `prefix + row`；
- `tl.dot` 计算 QK/PV，softmax 在 FP32，输出转回激活 dtype；
- 当 `sum(context) >= 4 * sum(q_len)`（前缀占主导）时启用，否则保留
  gather + FlashAttention，因为 2K 全量 prompt 上 FA 仍然更快；
- `cu_seqlens_k` 是累计值，context 长度必须用相邻差分，这一点有专门测试覆盖。

shared-prefix 的 TTFT 从 25.2 ms 降到 19.4 ms，已经与 nano-vllm 的 19.4 ms
持平。

## 3. Prefill QK-Norm + RoPE 融合

文件：`microinfer/layer/transformer.py`

`_compiled_qk_norm_rope` 把 Q/K 的 RMSNorm 和 RoPE 放进同一个
`torch.compile(dynamic=True)` 区域，只在 prefill 使用；decode 继续用 graph 内
的独立算子，避免影响已经稳定的捕获路径。每层少 2–3 次小 launch，single-short
的 TTFT 从 17.1 ms 降到 14.9 ms。

## 4. Graph 内 greedy argmax

文件：`microinfer/runner.py`

capture 时同时计算 `logits.argmax(-1)` 并保存 token buffer；replay 后 greedy
请求直接取 token，不再在 Python 边界多启动一次 argmax kernel。非 greedy 请求
仍然使用 logits。收益主要在单步固定开销，与第 3 项一起体现在 TTFT/TPOT。

## 复现

```bash
python -m bench.bench_offline --model /path/to/Qwen3-0.6B \
  --engine microinfer --workloads single-short,batch8-short,batch32-mixed,shared-prefix,long-prefill \
  --block-size 16 --num-blocks 1024 --max-num-prefill-tokens 8192 \
  --compile-ops --use-cuda-graph --runs 3 --warmup 1 \
  --output-dir results/bench/p6-all --tag p6-all
```

`tests/layers/test_triton_paged_attention.py` 覆盖 split-K decode 和 paged
prefill 与参考实现的数值一致性；完整测试为 350 passed, 1 skipped。
