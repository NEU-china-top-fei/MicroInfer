# P1 优化工作流

> 本文是 P1 的迭代日志，P1.0–P1.8 记录的是当时的状态。文末“仓库整理”列出了
> 后续删除的 test-only 接口；当前 API 以 [架构说明](architecture.md) 为准。

P1 的目标是去掉 decode 每步的 host 同步和 Python 开销，并为 P2 CUDA Graph
准备一个可静态化的执行路径。P1.0 只搭安全网，不改推理算法。

### `debug_mode` 现在检查什么

`debug_mode=True` 时：

- `Scheduler.add`：重复入队、空 prompt、长度/容量、已有 block table；
- `Scheduler.postprocess`：inflight 一致性、token 类型；
- `ModelRunner.validate_step`：
  - `cu_seqlens_q/k` 单调、端点、q/k 长度与 `num_cached_tokens + num_scheduled_tokens` 一致；
  - `max_seqlen_q/k` 与 cu_seqlens 一致；
  - `slot_mapping` 长度、非负、无重复、不越 KV 容量；
  - 每个 slot 与 block table 推导出的物理位置一致；
  - 每个 prefill/decode 的 position 与序列位置一致；
  - block table 覆盖 context、block id 非负且在池内；
  - token id 非负且不超过 vocab；
  - 有前缀复用时必须提供 block table。

`debug_mode=False` 时这些检查全部跳过，避免 host 同步和 Python 遍历。

**尚未迁移到开关下的检查**：`paged_attention` 的逐层校验、`LayerKVCache.write`
的范围/唯一性检查、`Sampler.probabilities` 的 logits 有限性检查。它们分别在
P1.1、P1.2、P1.8 处理；P1.0 保留这些检查，避免提前改变数值行为。

### `use_compile` 现在做什么

`ModelRunner._build_forward`：

```python
if not self.use_compile:
    return self.model.forward
return torch.compile(self.model.forward, dynamic=True, mode="default")
```

- 只编译 forward 调用，不把 `QwenModel` 包成 `OptimizedModule`，所以
  `bind_kv_cache`、`compute_logits`、测试仍能访问原始属性；
- 默认 `False`；
- 当前 `paged_attention` 的 `.tolist()` 和 `flash_attn` 自定义 op 会导致
  graph break，因此它只是一个实验开关，compile 调优在 P1.5；
- 不要和 `mode="reduce-overhead"` 混用：P2 会显式做 CUDA Graph。

## 用法

Python：

```python
from microinfer import LLM

llm = LLM.from_pretrained(
    "/path/to/Qwen3-0.6B",
    block_size=256,
    num_blocks=64,
    debug_mode=True,      # 测试/排查
    use_compile=False,    # P1.5 再打开

```

```bash
python -m microinfer --model /path/to/Qwen3-0.6B \
  --prompt 'Hello' --max-tokens 2 --greedy \
  --block-size 256 --num-blocks 64 --debug-mode
```

```bash

```

## P1.1 Metadata 对象化（已完成）

### 改了什么

| 位置 | 内容 | 为什么 |
| --- | --- | --- |
| `microinfer/layer/metadata.py` | 新增 `AttentionMetadata` | 每步只描述一次 cu_seqlens/slot/block table/context |
| `microinfer/utils/context.py` | `Context.metadata` 字段 | 兼容测试和直接调用；生产路径显式传 metadata |
| `microinfer/runner.py` | `prepare_*` 构建 metadata，`set_context(..., metadata=...)` | Runner 是唯一知道本步调度信息的地方 |
| `microinfer/runner.py` | `run_model(..., metadata)` | 把 metadata 显式传给模型，不再让每层读 ContextVar |
| `microinfer/model/qwen3.py` | `forward/compute_logits` 接收 metadata | 只在 packed 1D 输入时使用；dense 测试路径不变 |
| `microinfer/layer/transformer.py` | `Attention/TransformerLayer` 显式接收 metadata | 去掉每层 `get_context()` 和分支 |
| `microinfer/layer/cached_attention.py` | 不再 `torch.equal`、不再每层算 `cu_seqlens_k` 差分/`arange`/`tolist` | 每层重复工作变成每步一次 |
| `microinfer/layer/paged_attention.py` | 新增 `paged_attention_meta` 快路径 | 生产路径不校验、不 tolist；kernel dispatch 直接用 metadata |
| `microinfer/layer/paged_attention.py` | 保留 `paged_attention` 校验入口 | 独立调用/测试仍需要严格校验 |

关键设计：

- `AttentionMetadata.cu_q_cpu` / `context_lens_cpu` / `q_lens_cpu` 是**懒加载**的：
  - decode flash 路径完全不触碰它们；
  - prefill flash/参考路径第一次访问时 `.tolist()` 一次，之后 tuple 缓存；
- `paged_attention`（带校验）只给独立调用和测试用；引擎走
  `paged_attention_meta`，block table、context lens、cu_seqlens 都是
  `Runner` 已创建的 int32/连续 tensor；
- 直接 prefill 的逐请求 SDPA 仍保留，但它现在只读 metadata 的 CPU offsets，
  不再每层 `.tolist()`。

## P1.2 KV 写入快路径（已完成）

### 改了什么

| 位置 | 内容 | 为什么 |
| --- | --- | --- |
| `microinfer/layer/metadata.py` | `slot_mapping_long`、`slot_indices(block_size)`、`validate_cache_write` | 每步只做一次 `long()` 和 block/offset 计算，28 层复用 |
| `microinfer/worker/kv_cache.py` | `write_checked` + `write_fast`；`write` 保留为 checked 别名 | 生产路径删掉 `any`/`unique`/mask；测试仍走严格校验 |
| `microinfer/layer/cached_attention.py` | `validate_cache_write` 决定走 checked 还是 fast | debug 能保留完整校验，生产走零同步写入 |
| `microinfer/runner.py` | metadata 的 `validate_cache_write=self.debug_mode` | debug 开关统一控制校验路径 |
| `microinfer/layer/paged_attention.py` | 独立入口的 metadata 显式关闭 cache 校验 | 它不写缓存，校验没有意义 |

`write_fast` 的输入是 metadata 预计算好的 `blocks`/`offsets`：

```python
blocks, offsets = metadata.slot_indices(cache.block_size)
cache.write_fast(blocks, offsets, k, v)
```

`slot_indices` 按 `block_size` 缓存，第一次调用时计算：

```python
slots = metadata.slot_mapping_long
blocks = torch.div(slots, block_size, rounding_mode="floor")
offsets = slots - blocks * block_size
```

28 层共用一次 `.long()`、一次除法和一次取模。

## P1.3 RoPE 预计算（已完成）

### 改了什么

| 位置 | 内容 | 为什么 |
| --- | --- | --- |
| `microinfer/layer/rope.py` | 新增 `RotaryCache` | 一张 FP32 `cos/sin` 表，所有层共享 |
| `microinfer/layer/rope.py` | 保留 `comp_freq_cis` / `apply` / `rotate` | 公共算子契约和现有测试不变 |
| `microinfer/layer/transformer.py` | `Attention(config, rotary=None)` 使用 `rotary.apply` | 不再每层每步 `torch.polar`/算角度 |
| `microinfer/layer/transformer.py` | `TransformerLayer(config, rotary=None)` | 把共享 cache 传给 Attention |
| `microinfer/model/qwen3.py` | `QwenModel` 创建一个 `RotaryCache` 并传给所有层 | 28 层共享 20 MB 表，不再每层各建一份 |
| `microinfer/layer/__init__.py` | 导出 `RotaryCache` | 方便测试和后续 kernel 工作 |

`RotaryCache` 的实现要点：

- 表在第一次 forward 时按 activation device 懒构建，支持模型先构造后 `.cuda()`；
- `cos/sin` 始终以 FP32 存储，计算后转回 activation dtype，保持原数值口径；
- 按 position `index_select`，不再每层构造 `inv`、`angles`、`polar` 和复数；
- 支持 packed `[T,H,D]`、dense `[B,L,H,D]`、decode `[B,H,D]` 三种 shape；
- split-half（Qwen3 默认）和 interleaved 两种布局都支持；
- 表约 40960 × 64 × 4 × 2 ≈ 20 MB，显存峰值相应增加约 20 MB。

## P1.4 RMSNorm + residual 融合（已完成）

### 改了什么

| 位置 | 内容 | 为什么 |

| `microinfer/layer/norm.py` | `forward` 在 `fused_layer_norm=True` 时调用 `F.rms_norm` | 把 mean/pow/rsqrt/cast/mul 收敛到 fused kernel |

实现：

```python
if not self.is_fuse:
    return self._reference_forward(x, residual)

combined = x if residual is None else x + residual
normalized = F.rms_norm(
    combined, (combined.shape[-1],), self.norm.weight, self.eps
)
return normalized, combined
```

- `F.rms_norm` 在 CUDA 上使用 fused RMSNorm kernel，内部 FP32 累加；
- residual 仍返回给下一层；
- Q/K norm 复用同一个 `FuseLayerNorm` 类，因此也自动走 fused；
- `fused_layer_norm=False` 的 tiny test 配置仍走原来的逐 op 参考实现，
  保证测试覆盖两条路径。

## P1.5 torch.compile（已完成）

### 改了什么

| 位置 | 内容 | 为什么 |
| --- | --- | --- |
| `microinfer/runner.py` | `_compiled_forward` 只用于 decode，prefill 走 eager `_forward` | prefill 形状/循环变化大，收益低且容易 graph break |
| `microinfer/runner.py` | `_forward_for(is_prefill)` | 明确 decode-compiled / prefill-eager 的路由 |
| `microinfer/runner.py` | compile 前调用 `rotary.ensure(device)` | 避免 Dynamo 追踪 40960 行 RoPE 表构造 |
| `microinfer/layer/cached_attention.py` | 删除 `q_lens_cpu != context_lens_cpu` 的 Python list 比较 | 该比较在 Dynamo 中是 data-dependent guard，会产生 graph break；不变量由 Runner debug 校验和 metadata 构建保证 |
| `microinfer/layer/rope.py` | `ensure()` 公开，`_ensure` 兼容别名 | Runner 可以在 compile 前建表 |
| `bench/profile_runner.py` | `--use-compile` | 可以 profile compiled decode |
| `tests/components/test_runner.py` | `test_compile_is_decode_only` | 防止把 compile 误用到 prefill |

设计：

```python
self._forward = model.forward                    # prefill + fallback
self._compiled_forward = torch.compile(
    model.forward, dynamic=True, mode="default"
)                                                # decode only

def _forward_for(self, is_prefill):
    if self._compiled_forward is not None and not is_prefill:
        return self._compiled_forward
    return self._forward
```

为什么 decode-only：

- prefill 的 `CachedAttention` 直接路径有 Python 逐请求循环、可变长度；
- decode 的 batch/形状更稳定，compile 收益最大；

## P1.6 QKV / FFN 打包（已完成）

### 改了什么

| 位置 | 内容 | 为什么 |
| --- | --- | --- |
| `microinfer/layer/transformer.py` | `Attention.fuse_weights()` | Q/K/V 合并成一次 GEMM `[Hq+2Hkv]*D` |
| `microinfer/layer/transformer.py` | `FFN.fuse_weights()` | gate/up 合并成一次 GEMM `2*inter` |
| `microinfer/layer/transformer.py` | 非持久 buffer `qkv_weight/qkv_bias/gate_up_weight/gate_up_bias` | 不进 state_dict，加载后 fuse，forward 走 packed 路径 |
| `microinfer/model/qwen3.py` | `QwenModel.fuse_weights()` | 遍历所有层 fuse |
| `microinfer/llm.py` | `from_model/from_pretrained(fuse_weights=True)` | 默认加载后打包；可关闭 |
| `microinfer/__main__.py` / `bench/` | `--no-fuse-weights` | 对比/低显存运行 |
| `tests/model/test_qwen3.py` | fused vs unfused 输出一致、buffer 不持久、幂等 | 数值和生命周期验收 |
| `tests/integration/test_hf_parity.py` | parity 模型也 fuse | 覆盖真实 fused 路径 |

实现方式：

```python
qkv = F.linear(x, self.qkv_weight, self.qkv_bias)
q, k, v = qkv.split([Hq * D, Hkv * D, Hkv * D], dim=-1)

gate_up = F.linear(x, self.gate_up_weight, self.gate_up_bias)
gate, up = gate_up.chunk(2, dim=-1)
```

- 原始 `q_proj/k_proj/v_proj` 和 `gate_project/up_project` 不保留独立存储：
  fuse 后它们的 `Parameter` 被替换成 **fused buffer 的视图**，共享同一块 storage；
- checkpoint 映射、`state_dict` key、`bind_kv_cache` 都不变；
- 因此稳态显存与未打包版本相同，没有额外 560 MB；fuse 时 `torch.cat` 会短暂分配
  一份 packed tensor，但加载完成后旧参数被释放，benchmark 的稳态峰值回到 ~2.97 GB；
- `--no-fuse-weights` 仍保留，用于 A/B 或排查 view 相关问题。

注意：`fuse_weights()` 应在 `.to(device/dtype)` 之后调用（引擎的
`from_pretrained` 已经这样做）。如果 fuse 之后再把整个模型 `.to()`，PyTorch 会
为 Parameter 新建 storage，视图不再共享；此时需要重新 fuse。

## P1.8 Host 开销收尾（已完成）

### 改了什么

| 位置 | 内容 | 为什么 |
| --- | --- | --- |
| `microinfer/runner.py` | `_DecodeBuffers`：pinned CPU staging + 复用 device buffer | 去掉每步 `torch.tensor(list, device="cuda")` 的 H2D 同步 |
| `microinfer/runner.py` | `prepare_decode` 原地填充 5 个字段并 `copy_(non_blocking=True)` | 保留异步拷贝，kernel 在同一 stream 上消费 |
| `microinfer/runner.py` | block table 固定宽度 buffer，padding 写 `-1` | decode block table 宽度稳定，为 P2 静态 buffer 铺路 |
| `microinfer/runner.py` | `Runner.run` 用 Python `all(greedy_flags)` | 删除 `greedy.all()` 的 host 同步 |
| `microinfer/layer/sampler.py` | `Sampler(validate=...)`，`probabilities` 只在 debug 校验 | 生产路径去掉全词表 `isnan/isposinf/isfinite` 检查 |
| `microinfer/llm.py` | `Sampler(validate=config.debug_mode)` | debug 模式保留完整校验 |
| `tests/components/test_runner.py` 等 | 现有 decode/engine/parity 测试覆盖新 buffer | 行为不变 |

关键点：

- 第一次 decode 时按 batch/宽度分配 pinned + device buffer，之后复用；batch 或宽度
  增长才重新分配；
- `input_ids`/`positions` 是 int64，`slot_mapping`/`context_lens`/`block_tables`
  是 int32；
- `copy_(..., non_blocking=True)` 只在 pinned 时开启；
- block table 的 padding 每个 step 写 `-1`，有效列来自 `seq.block_table`；
- `tokens.tolist()` 保留：Scheduler 需要 CPU token 才能决定 append/停止，这是
  架构性同步，P2 的 CUDA Graph 也去不掉。
